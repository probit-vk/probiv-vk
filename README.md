**[Пробив ВК](https://github.com/probit-vk)** — экосистема инструментов для поиска информации о профиле по VK ID, username и ссылке. Этот репозиторий описывает основной продукт: какие исходные данные принимает поисковая система, как устроен поиск по собственному индексу и из каких разделов может состоять результат.

Чтобы пробить ВК, передайте сервису известный идентификатор страницы. Это может быть числовой ID, короткий адрес или полная ссылка `vk.com`. Система приводит входное значение к единому формату, определяет профиль и сопоставляет его с записями в собственном индексе.

> Используйте поиск только в законных целях. Наличие конкретных полей и глубина истории зависят от записей, которые уже присутствуют в индексе.

## Быстрый старт

Поиск начинается с одного известного значения:

```text
https://vk.com/id123456
https://vk.com/username
id123456
123456
username
```

1. Откройте [Telegram-бота](https://bot-probiv.org/).
2. Отправьте ссылку, VK ID или username.
3. Дождитесь сопоставления идентификатора с индексом.
4. Изучите найденные сведения и историю изменений.

Если исходным значением является короткая ссылка, сначала определяется числовой VK ID. Благодаря этому записи об одном профиле не разделяются между старым и новым username.

## Что делает поисковая система

Основная задача сервиса — объединить записи, относящиеся к одному профилю. Обработка запроса проходит в несколько этапов:

1. определяется тип входного значения;
2. ссылка или username преобразуется в идентификатор;
3. выполняется поиск совпадений в собственном индексе;
4. связанные записи группируются по профилю;
5. пользователю формируется структурированный отчёт.

В зависимости от покрытия индекс может содержать основные сведения о странице, использовавшиеся ранее имена и username, историю аватаров, связанные упоминания и ранее проиндексированные контактные данные. Если нужной записи нет, поле не добавляется в отчёт как установленный факт.

## Собственный индекс и история профиля

Состояние страницы на текущий момент — не единственный источник результата. Поисковая система использует собственный индекс, который хранится отдельно от серверов ВКонтакте. Поэтому изменение username, аватара или настроек видимости страницы не удаляет записи, сохранённые ранее.

Для закрытого профиля поиск также начинается с VK ID или ссылки. Сервис проверяет, имеются ли в индексе исторические снимки и связанные записи. Результат может включать:

- прежние имена и короткие адреса;
- ранее использовавшиеся изображения профиля;
- даты обнаруженных изменений;
- связанные страницы и упоминания;
- проиндексированные ранее контакты, если они присутствуют в базе.

Закрытие страницы не означает, что система обязательно располагает полной историей. Оно лишь не удаляет уже сохранённые записи из независимого индекса.

## Форматы поиска

### По VK ID

Числовой идентификатор — наиболее устойчивый способ определить страницу. Он не меняется вместе с username и подходит для сопоставления исторических записей.

Подробная инструкция: [поиск по ID, ссылке и username](https://github.com/probit-vk/probiv-vk-po-id-ssylke-yuzu).

### По ссылке или username

Полная ссылка `vk.com/id...` уже содержит идентификатор. Короткий адрес `vk.com/username` сначала преобразуется в VK ID, после чего поиск продолжается по индексу.

### По профилю или аккаунту

Если известна страница пользователя, её можно проверить как профиль или аккаунт. Входное значение при этом остаётся тем же: ссылка, ID либо username.

Практические примеры: [поиск по странице, профилю и аккаунту](https://github.com/probit-vk/probiv-vk-profil-stranica-akkaunt).

### По номеру телефона

Телефон может использоваться как отдельное исходное значение для проверки совпадений. Обратный поиск также возможен, когда ранее проиндексированный контакт связан с установленным VK ID. Результат зависит от фактического наличия такой связи в базе.

Подробнее: [поиск по номеру телефона](https://github.com/probit-vk/probiv-vk-po-nomeru-telefona).

## Состав отчёта

Отчёт формируется из найденных записей, а не из заранее заданного набора обещаний. В нём могут присутствовать:

| Раздел | Что показывает |
|---|---|
| Идентификаторы | VK ID, текущие и прежние username |
| Профиль | имя, описание и связанные сведения |
| История | обнаруженные изменения страницы |
| Изображения | текущие или сохранённые ранее аватары |
| Связи | совпадения с другими записями индекса |
| Контакты | ранее проиндексированные данные при наличии |

Каждое поле следует воспринимать в контексте даты записи. Историческое значение может уже не соответствовать текущему состоянию профиля.

## Частые вопросы

### Можно ли пробить ВК по одной ссылке?

Да. Ссылка позволяет определить VK ID, после чего система ищет профиль и связанные с ним исторические записи в собственном индексе.

### Что произойдёт, если username изменился?

Поиск ориентируется на устойчивый идентификатор страницы. Если старый и новый username ранее были связаны с одним VK ID, они могут быть объединены в истории профиля.

### Можно ли проверить закрытую страницу?

Да, если профиль определяется по ссылке или ID. Текущие настройки видимости не удаляют историю, которая была сохранена в индексе ранее. Полнота ответа зависит от покрытия базы.

### Почему некоторые разделы отсутствуют в отчёте?

Сервис показывает только найденные совпадения. Если индекс не содержит подтверждённой записи для конкретного поля, это поле не включается в результат.

### Где запустить поиск?

Рабочая точка входа — [Telegram-бот](https://bot-probiv.org/). Репозитории организации содержат описание форматов запросов и отдельных сценариев поиска.
